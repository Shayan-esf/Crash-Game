# معماری سرور (Server Architecture)

## ساختار پروژه

```
server/
├── config.js              # پیکربندی و تنظیمات سرور
├── index.js               # فایل اصلی و راه‌انداز سرور
├── controllers/           # کنترلرها
│   └── websocketController.js
├── services/              # منطق تجاری (Business Logic)
│   └── gameService.js
├── utils/                 # ابزارها و توابع کمکی
│   └── telegram.js
└── middleware/            # میان‌افزارها (Middleware)
```

## کامپوننت‌ها

### config.js
پیکربندی متمرکز سرور:
- تنظیمات وب‌سوکت (WebSocket)
- پیکربندی ردیس (Redis)
- توکن‌های ربات تلگرام
- پارامترها و ضرایب بازی
- کانال‌های pub/sub

### services/gameService.js
منطق اصلی بازی:
- مدیریت وضعیت و فازهای بازی
- محاسبه لحظه‌ای ضرایب در زمان واقعی
- راه‌اندازی و خاتمه بازی‌ها و تسویه حساب
- کار با تاریخچه سشن‌ها

### controllers/websocketController.js
پردازش پیام‌های وب‌سوکت:
- احراز هویت کاربران
- پردازش شرط‌ها و کش‌اوت (برداشت سود)
- مدیریت چت
- همگام‌سازی وضعیت کلاینت‌ها

### utils/telegram.js
توابع کمکی کار با تلگرام:
- اعتبارسنجی initData
- استخراج اطلاعات کاربر
- حالت DEV برای تست و توسعه

## راه‌اندازی

```bash
# سرور قدیمی
npm run ws

# سرور جدید ماژولار
npm run ws-new
```

## مزایای معماری جدید

۱. **ماژولار بودن** - تفکیک وظایف هر کامپوننت
۲. **خوانایی بالا** - تقسیم کد به بلوک‌های منطقی
۳. **تست‌پذیری** - سهولت در نگارش تست برای هر ماژول
۴. **مقیاس‌پذیری** - افزودن ساده ویژگی‌های جدید
۵. **پشتیبانی و نگهداری** - عیب‌یابی و رفع سریع خطاها

## اصول طراحی

- **Single Responsibility** - هر کلاس تنها مسئول یک وظیفه است
- **Dependency Injection** - تزریق وابستگی‌ها از طریق سازنده
- **Configuration First** - تمرکز تمام تنظیمات در یک نقطه
- **Error Handling** - مدیریت متمرکز و یکپارچه خطاها
